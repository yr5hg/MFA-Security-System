# Part 8 — frozen-policy evaluation

Run `node scripts/evaluate-verification.js --self-test`, then `node scripts/evaluate-verification.js <private-dataset-directory> 3` on Windows and Kali. The existing P01/P02/P03 folders need only `reference.jpg` and `test1.jpg` for this test. Keep all inputs outside Git; do not print or store reference descriptors. Use authorized consenting participants only.

The script enrolls one reference per participant via the actual public interface. For each round it compares every held-out probe against every reference. With three participants, the first round gives 3 genuine and 6 impostor pairs. Repeating those pairs gives timing and consistency observations, **not independent biometric trials**. The original held-out photos have already been evaluated in Part 6, so this is an interface-level reproduction, not a new independent validation set. Hamzeh should separately test newly captured, consenting samples without adjusting the policy (0.66). Denied genuine attempts include operational errors; report those separately from score mismatches. The score threshold remains provisional for the isolated lab only.

Wall time is measured immediately around each public method call. It includes child startup, model initialization, IPC and cleanup on successful replies, but not browser capture, network, Keycloak or session handling. The verifier's inference time is a separate reported measurement when available. Each request starts a fresh child process; operating-system caches may be warm. No end-to-end authentication timing claim is supported. Record medians, ranges, CPU, RAM, OS and counts. Run Kali with the deployment model directory and external network disabled later as part of Part 9, after model staging.

The script also resubmits the exact enrollment JPEG locally. This is a reference-image reuse test only, not a physical spoofing or browser replay test. For separate authorized lab presentation trials, with participant consent use their printed photo, screen-displayed photo, and prerecorded video shown to the actual webcam. Record genuine/impostor/presentation category, outcome and count without saving images, scores tied to identities or credentials. Do not infer liveness or challenge replay protection from local matching; the trusted gate owns attempt/challenge binding. If tests are not run, report them as pending. Do not tune threshold based on held-out results.
